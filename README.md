# EXVS FHM2D Unpack

> 目前只有解包功能是比较完整可用的。
> 立绘预览、图片替换和 FHM2D 反向回包仍在持续整理。
> 其他功能和实验性代码请当作代码参考使用。

## 当前版本风险与原因（重要）

当前版本的解包、纹理目录和静态预览功能相对成熟，FHM2D 回包与自动部署仍属于
实验功能。请始终保留未经修改的游戏原始文件，不要把结构扫描通过等同于游戏内一定
能够加载。

主要风险和原因如下：

- **很小的容器元数据差异可能导致整个包完全不显示。** FHM2D 的压缩块目录、
  相对偏移、压缩长度和包尾分组元数据会被游戏作为一个整体解析。即使 110 张纹理
  本身全部有效，只要一个终止长度或尾部引用不正确，游戏也可能放弃整个包，而不是
  只丢失一张图片。
- **必须从固定的原始基底构建。** 已经修改过的 FHM2D 可能带有不同的压缩块边界
  和索引值。继续把修改包当作下一次构建的源文件会放大未知差异，因此工具会保存并
  优先使用原始基底，避免递归回包。
- **结构验证不能替代游戏内验证。** 当前校验会检查纹理数量、尺寸、格式、payload、
  Deflate 块、索引引用和尾随数据，但仍无法复现游戏加载器的全部隐藏约束。未逐包
  进行游戏内测试的文件仍可能加载失败。
- **未识别结构不应强制回包。** 不在人物映射数据库中的包、未知纹理格式、未知尾部
  类型、`payload_size_mismatch` 或索引布局无法识别的包，均应视为尚未适配。
- **图片合规不等于容器合规。** 自动缩放、RGBA 转换、BC7 编码和透明区规范化可以
  降低图片层风险，但不能修复错误的 FHM2D 容器索引。反过来，容器能够加载也不代表
  眼睛、嘴部和主体的 Alpha 空隙及坐标一定正确。
- **RGBA8 回包验证仍少于 BC7。** RGBA8 已完成批量提取和 PNG 验证，但修改回包与
  游戏内替换样本仍不足，风险高于已经做过实际替换测试的 BC7 工作流。

本版本已修复一次会造成整包空白的回归：解码器曾丢失
`0x39FB3F2F.fhm2d` 末尾 5,340 字节的分组元数据，同时没有更新索引中的压缩载荷
终止长度。修复后，使用旧成功纹理重新构建的文件已经与历史上能够在游戏内显示的
成功包逐字节一致。使用当前新图生成的修复包已通过结构校验，但仍需要完成游戏内
显示确认后，才能把该组新图标记为运行时验证通过。

EXVS 系列街机资源目录的便携式 FHM2D 纹理解包、立绘映射与预览工具。

工具包内置 Python、Pillow、NumPy 和 DirectXTex Texconv，目标电脑无需单独安装 Python 环境。当前工作流主要面向 `vsac29` 数据集，支持从 FHM2D 中提取已确认的 BC7/RGBA8 纹理，建立人物立绘映射，并在预览器中组合、检查和替换立绘图层。

> 说明：本项目用于资源学习、研究和个人备份流程验证。请勿用于分发版权资源，也不要让工具直接覆盖游戏目录中的原始 FHM2D 文件。

## 快速开始

将整个工具目录放在任意 `vsac*_Release.exe` 的同级目录：

```text
游戏目录/
  vsac*_Release.exe
  data/
  EXVS_Texture_Toolkit/
```

根目录提供三个启动入口：

```text
启动解包工具.bat
启动立绘查看器.bat
启动单文件解包压缩工具.bat
```

首次使用建议按这个顺序执行：

1. 运行 `启动解包工具.bat`。
2. 执行“一键建立完整立绘库”，按当前提取结果生成纹理目录和人物映射。
3. 全量流程会在映射完成后自动整理 `workspace/all-textures/packages`；增量提取完成后可点击“重新分类现有图片”，无需重新扫描或提取 PNG。

三个本地页面使用互不重叠的自动回退端口段：立绘查看器
`17865-17874`、解包工具 `17875-17884`、单文件工具
`17885-17894`。启动脚本仍能打开旧端口上已经运行的对应服务。
3. 等待提取、目录生成和人物映射完成。
4. 运行 `启动立绘查看器.bat` 预览和测试立绘组合。

## 单文件解包压缩工具

`启动单文件解包压缩工具.bat` 是独立的小工具，不依赖完整资源扫描或人物映射。
它不会改变原有“解包工具”和“立绘查看器”的工作区流程。

1. 选择一个 `.fhm2d` 文件和工程输出目录，点击“提取”。
2. 在生成工程的 `png_edit` 文件夹内编辑 PNG。保留文件名、原始尺寸、8-bit RGBA
   格式和透明通道。
3. 选择包含 `project.json` 的工程文件夹，点击“构建 FHM2D”。

默认工程位于 `workspace\single-fhm2d-projects\<包名>`，回包文件位于该工程的
`build` 子目录。工具禁止覆盖工程记录的原始 FHM2D；已存在的工程或输出文件也需要
用户明确勾选覆盖选项。

这里的“单文件”表示可以自行指定输入路径，不表示所有未知 FHM2D 结构都已支持。
未知容器、纹理格式、payload 长度或索引结构会被拒绝，并在任务日志中显示原因。

旧版工具提取的 PNG 如果在 Windows“照片”、浏览器或图像编辑软件中明显发白，请在解包工具中执行一次“修复显示颜色”。该操作只把错误的线性 Gamma 标记改成标准 sRGB，不修改任何 RGBA 像素，也不影响后续回包。

## 主要功能

- 扫描 `data\x64\dplcache_release` 下的 FHM2D 文件。
- 断点续跑提取通过元数据校验的通用 `46XT*` BC7/RGBA8 纹理，包括 `46XTimg`、`46XTms`、`46XTvs` 等命名族。
- 重建 BC7/RGBA8 DDS，并转换为 RGBA PNG。
- 为 PNG 写入标准 sRGB 显示标记，保证常用查看器和编辑软件颜色一致。
- 生成全局纹理目录和逐图验证报告。
- 自动识别领航员、战斗人员、觉醒立绘、刷卡喜好机体、选机界面机体/领航员和匹配界面机体图。
- 可重新扫描 `workspace/all-textures/packages` 中已有图片并更新分类目录与查看器映射。
- 组合主体、眼睛、嘴部和表情状态图层。
- 上传 PNG、JPEG、WEBP、BMP 或 DDS，软件会自动转为 RGBA PNG，必要时按比例缩放并透明补边。
- 将替换图保存在 `workspace\asset-mapping\replacements`。
- 自动定位替换图涉及的 FHM2D 包，按原始 BC7/RGBA8 格式构建补丁。
- 部署前逐包备份并校验 SHA-256，可从查看器恢复最近备份。
- 根据当前提取结果自动分析人物分类、图层坐标和组合关系。

## 构建与部署

立绘查看器顶部提供三个游戏文件操作：

1. `构建补丁`：扫描全部替换图，自动定位涉及的 FHM2D 包，在工作区生成修改版文件。
2. `备份并部署`：确认游戏进程已关闭，备份原文件并部署最新构建。
3. `恢复备份`：恢复最近一次仍处于部署状态的备份。

构建结果、备份和操作清单位于：

```text
workspace\patch-build\
  outputs\
  backups\
  manifests\
```

部署和恢复会校验源文件、构建文件与备份的 SHA-256。当前游戏文件如果在构建后被其他程序修改，工具会拒绝覆盖。部署中断时会保留 `deploying` 清单，重新启动查看器后仍可执行“恢复备份”。

当前自动回包部署仍以原始 FHM2D 纹理的 BC7/RGBA8 元数据为准。上传图片的格式会先转换为 RGBA PNG，回包时不会直接使用用户上传的 DDS 参数；如果尺寸、mipmap 或纹理结构无法保持，构建会拒绝覆盖游戏文件。

## 当前回包边界

在当前测试数据中，已分类的 524 个 FHM2D 图片包可以使用本工具进行图片导出、PNG 编辑、按原始纹理格式编码和 FHM2D 回包。已覆盖 BC7、RGBA8、BC7/RGBA8 混合包，以及已识别的 `LMB` 尾部、特殊 payload 分块、批量索引表和少量索引填充差异。

这表示工具已经通过结构级验证和代表性完整流程测试，但不等同于 524 个包都已经逐个在游戏内验证。实际替换时仍应先处理一个包，确认游戏显示正常后再批量部署，并始终保留原始文件备份。

未进入人物映射数据库的 FHM2D 不属于当前图片回包支持范围。全量扫描中还存在音频、特效、杂项资源和未识别结构；这些文件可以使用结构扫描器分析，但不能直接套用人物图片的回包流程。

即使文件包含图片数据，如果扫描报告出现 `payload_size_mismatch`、未知尾部类型、未知纹理格式或索引结构错误，也应视为未适配包。工具应拒绝强行覆盖游戏文件，等待该结构完成单独分析和回包测试。

## 纹理格式支持

### PNG 编辑要求

- 文档色彩空间使用 `sRGB IEC61966-2.1`。
- 保持原始宽高和 RGBA 四通道，不改变画布尺寸。
- 不要因为旧 PNG 看起来发白而手工应用 Gamma、曝光或曲线校正；应先运行“修复显示颜色”。
- 导出 PNG 时保留标准 sRGB 配置。回包器会按像素数值编码，并忽略显示配置，不会把色彩配置写入 FHM2D。

### BC7

FHM2D 格式码：

```text
0x4E0 -> BC7_UNORM
```

已完成：

- DDS DX10 头重建。
- Texconv 转 RGBA PNG。
- PNG 重新编码为 BC7。
- top mip 替换。
- deflate 数据块和 FHM2D 索引重建。
- 无修改回封字节一致性验证。
- 修改版游戏内加载测试。

全量数据中已提取并验证 25,973 张 BC7 图片。

### RGBA8

FHM2D 格式码：

```text
0x400 -> R8G8B8A8_UNORM
```

全量数据中已提取并验证 14,352 张 RGBA8 图片，已检查：

- PNG 为 RGBA 模式。
- 分辨率与元数据一致。
- 像素数据长度与格式一致。

目前 RGBA8 已完成提取、目录和 PNG 验证，尚未达到 BC7 工作流同等级的修改回封和游戏内替换验证。

### 杂项和 UI 纹理

工具可以提取属于已确认 BC7/RGBA8 格式的 UI、背景和其他杂项纹理，但目前没有为这些资源建立统一的语义分类或组合规则。

以下两个与人物目标尺寸相同但结构歧义的 UI 组已明确排除：


## 当前边界

- “全部纹理”仅指通过名称、`TEX` 标记、长度、尺寸、Mip、数组、深度和格式联合校验的 `46XT*` BC7/RGBA8 结构。
- 不包含尚未识别的其他纹理容器或 GPU 格式。
- 预览器复现静态图层坐标，不等于复现游戏完整动画状态机。
- 游戏运行时何时选择某个眼睛或嘴部状态，仍由游戏逻辑控制。
- RGBA8 修改回封尚未达到 BC7 工作流的验证程度。
- 不要让程序直接覆盖游戏目录下的原始 FHM2D。
